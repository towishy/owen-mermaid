# Lucian UX/UI: six original workflow specimens

## Source and decision

[Upstream](https://github.com/Seokwoooo/lucian-uxui-prompt/tree/7e339faa1cc5e87496cb7ce556a5b22aadbe76f8) is an interactive code gallery, not only a prompt collection. The approved selection is 127, 130, 176, 177, 191 and 201. The [collection](D:/GITHUB/wiki/lib/lucian-uxui/collection.json) pins all six original snippets, shared tokens, localization helper and full MIT license.

`adapt` means local routes, isolated execution, variants and delivery only. Original geometry, copy, CSS and script are not reinterpreted. Continuous corners apply to the touched Portal shell, not to upstream specimens.

## Useful mechanisms

- Package a concrete interaction, its source, metadata, localized description and declarative demonstration together.
- Search before fetching; deliver only one explicitly selected original packet, never the full upstream catalog.
- Include insertion/replacement targets, data/event preservation, token mapping, lifecycle cleanup and unverified checks in the porting prompt.
- Keep original-snippet packets distinct from public Foundation export packets. Both use the existing source-packet schema; neither source identity nor a demo is consumer acceptance.

## Runtime and fidelity boundary

Original HTML/CSS/JS is rendered inside an opaque-origin iframe with a no-network CSP. The local outer host provides source attribution and status; Portal owns the mode selector, theme/locale variants and opt-in demo commands.

The declarative player implements the selected sources' `wait`, `tap`, `drag` and `reset` operations. It does not evaluate arbitrary demo JavaScript. Reset, stop and navigation replace the source execution context; trusted user input cancels automatic steps.

Initial-state captures record source/revision, implementation input digest, viewport, DPR, locale, theme, reduced-motion mode, browser and PNG hashes. Full paired original/local comparison and interaction acceptance are pending; standalone host layout is not claimed to reproduce the upstream gallery shell.

## Product adoption boundary

Existing Foundation primitives remain preferred for general product UI. A product port must connect real data and events, clean up side effects, satisfy the continuous-corner design contract and record any deliberate change from the original. A simulated approval, restored version, event playback or completed pipeline is not a backend implementation.
